4. Technical Difficulty Resolved / Defect Fixed

Problem: In a multi-stage workflow, a caller could easily introduce temporal coupling bugs by invoking operations in an illegitimate order (e.g. attempting to approve a book loan before validating student quotas or catalog availability, or re-approving an already active loan). Furthermore, standard exception-driven validation frequently obscured domain failures and broke pipeline purity.

Functional Solution: I solved this by modeling the loan lifecycle as a closed algebraic data hierarchy (abstract record LoanState with Draft, Validated, Approved, and Rejected) coupled with Result<T, DomainError> transitions. The constructor of Draft validates basic syntax, ValidateDraft verifies quotas using pattern matching on BorrowerTier, and ApproveLoan uses an exhaustive switch expression that accepts only Validated states. If a caller passes a Draft or an already Approved loan into ApproveLoan, the compiler and runtime cleanly return a structured Result.Failure("InvalidStateTransition") without mutating state or throwing unhandled exceptions.
